## Overview

The **Digital Plagiarism Checker & String Search Workbench** is a high-performance C++ system designed to solve two core information retrieval tasks:
1. **Exact Pattern Matching**: Fast searching of single queries across text using polymorphic algorithmic strategies (Naive, Knuth-Morris-Pratt, and Rabin-Karp).
2. **Lexical & Syntactic Plagiarism Detection**: Quantifying document similarity between two texts using token-level Jaccard similarity and $N$-gram sequence overlap.

The system provides dual interfaces: a headless Command-Line Interface (CLI) and an interactive **Dear ImGui** Desktop GUI (OpenGL3 / GLFW).

### 2. Algorithmic Search Engine (Strategy Pattern)
- **`IHashStrategy` & Implementations (`PlagiarismCore.hpp:143-234`)**
  - **`NaiveStrategy`**: Brute-force sliding window comparison ($O(n \cdot m)$ worst case).
  - **`KMPStrategy`**: Linear matching using a precomputed prefix function / LPS array ($O(n + m)$).
  - **`RabinKarpStrategy`**: Rolling hash matching using a 64-bit polynomial base with exact character verification on match ($O(n + m)$ average).
  - **`HashStrategyFactory`**: Factory returning `std::unique_ptr<IHashStrategy>` based on string identifier (`"rabin"`, `"kmp"`, `"naive"`).
  - **`SearchEngine`**: Orchestrator encapsulating the strategy execution.

## Data Flow

### Flow 1: Document Similarity Comparison
1. User supplies `file1.txt` and `file2.txt` (via CLI or GUI).
2. `TextDocument` loads content into memory.
3. `Tokenizer` decomposes content into token lists.
4. `NGramGenerator` constructs $N$-gram sets of chosen size $N$.
5. `PlagiarismChecker` calculates intersection over union for tokens and $N$-grams.
6. GUI renders progress bars, percentage values, and side-by-side text; CLI outputs summary.

### Flow 2: Pattern Search & Benchmark
1. User supplies target file, pattern, settings (case, whole-word, verify), and algorithm choice.
2. `HashStrategyFactory::create()` instantiates the selected `IHashStrategy`.
3. High-resolution clock starts.
4. Strategy searches document text and records occurrence offsets into `SearchResult`.
5. High-resolution clock stops to record elapsed microseconds.
6. Results (match count, locations, benchmark) are rendered in GUI / terminal and optionally written to `search_output.txt`.
